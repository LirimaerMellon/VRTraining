# VR Training — тренажёр прохождения сценария

Unity/URP-тренажёр: игрок проходит сценарий, состоящий из групп шагов
(например «Проверка документов»). Каждый шаг — одно ожидаемое действие:
дойти до точки, взять предмет, кликнуть по объекту или нажать кнопку.
Порядок и цель каждого действия проверяются автоматически; по завершении
показывается экран результатов с кнопками «Попытаться ещё» и «Возврат в
Лобби».

## Архитектура

Событийная архитектура без DI: объекты сцены (точки интереса, предметы,
кликабельные объекты, UI-кнопки) не знают о сценарии — они просто публикуют
факт своего действия в статическую шину `ScenarioEvents`. `ScenarioController`
слушает эту шину, сверяет действие с ожидаемым шагом через `ActionValidator`
и сам решает переходы между шагами/группами. UI, звук и подсветка независимо
друг от друга подписаны на те же события и ничего не знают ни друг о друге,
ни о контроллере — любую из этих систем можно заменить, не трогая остальные.

## Видение более гибкой системы сценариев

Сейчас сценарий — линейный список групп шагов. Более гибкой была бы
**графовая** модель: у шага появляется список возможных «следующих» шагов
(или условие перехода) вместо жёсткого индекса, и `ScenarioController`
хранит текущий узел графа, а не `currentStepIndex`. Это позволило бы
ветвление (разные последствия за разные действия) и необязательные шаги —
то, что невозможно выразить линейным списком. Архитектура уже к этому
готова: данные отдельны от логики, а логика реагирует на события через
конечный автомат — менять пришлось бы только структуру данных и правило
«что считать следующим шагом», не трогая Actions/UI/Audio/Highlighting.

## Как протестировать

Чтобы пройти сценарий, нужно открыть и запустить сцену **`Assets/Scenes/Training.unity`**
(не `Lobby`) и нажать Play.

## Управление (тестирование мышью/клавиатурой, без VR-шлема)

- **WASD** — ходьба
- **ПКМ (удерживать)** — осмотреться
- **ЛКМ** — навести прицел (белая точка в центре экрана) на предмет/кнопку
  и нажать, чтобы активировать его

## Структура скриптов

```
Assets/Scripts/
  Core/            — данные сценария
  Events/          — событийная шина
  Actions/         — источники действий игрока
  Scenario/        — проверка действий и логика прохождения сценария
  Highlighting/    — подсветка нужных объектов
  Audio/           — звуковая обратная связь
  UI/              — интерфейс (лобби, статус шагов, результаты)
  SceneManagement/ — переходы между сценами
Assets/Resources/example_scenario.json — сценарий: 3 группы по 3 шага
Assets/Scenes/Lobby.unity, Training.unity
```

## Как изменить сценарий

Отредактировать `Assets/Resources/example_scenario.json`: каждый шаг —
`description` (текст для игрока), `expectedAction` (0=дойти до точки,
1=взять предмет, 2=кликнуть по объекту, 3=нажать кнопку) и `target`
(идентификатор, должен совпадать с полем `targetId` на нужном объекте
сцены).

## Открыть проект на другом компьютере

Unity Hub → Add project (указать папку с `Assets`) → версия редактора
**6000.3.10f1** (или новее в той же основной ветке) → Unity сама подтянет
нужные пакеты при первом открытии.
